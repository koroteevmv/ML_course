#### Методические указания

##### Почему текст — это особые данные

Табличные данные (числа, категории) модели «понимают» напрямую. Текст — нет: модель ждёт на входе вектор чисел фиксированной размерности, а текст — это последовательность символов произвольной длины. Поэтому перед применением любой модели нужно **превратить текст в числа**.

Основные трудности при работе с текстом:

- **Переменная длина.** Один документ — это 5 слов, другой — 5000.
- **Дискретность и разреженность.** Слова — это символы, а не числа; между ними нет естественной метрики.
- **Морфология.** «Кошка», «кошки», «кошке» — разные токены, но одна сущность. Нужна лемматизация или стемминг.
- **Многозначность и контекст.** Слово «ключ» может означать гаечный ключ, родник или ключ к шифру. Контекст важен, но классические модели его «не видят».
- **Шум.** HTML-теги, цитаты, подписи, опечатки, эмодзи — всё это мешает.
- **Язык.** Русский, английский, китайский — разные правила токенизации, морфологии, стоп-слов.

Есть три основных подхода к векторизации текста (в порядке возрастания сложности):

1. **Bag of Words (BoW)** — считаем частоты слов в документе. Просто, быстро, часто хорошо работает как baseline.
2. **TF-IDF** — взвешиваем частоты с учётом того, насколько слово редкое в корпусе. Обычно лучше BoW.
3. **Эмбеддинги** — представляем слова (или целые документы) плотными векторами, обученными на больших корпусах. Учитывают семантику, но требуют больше данных и ресурсов.

В этой работе мы подробно разберём BoW и TF-IDF (это «рабочие лошадки» классического ML для текстов), а эмбеддинги затронем обзорно.

##### Предобработка текста

Типичный конвейер предобработки:

```
сырой текст → нижний регистр → удаление пунктуации/цифр/HTML
            → токенизация → удаление стоп-слов
            → стемминг или лемматизация → список токенов
```

Рассмотрим каждый шаг.

**Приведение к нижнему регистру.** «Кошка» и «кошка» — разные токены, если не привести к нижнему регистру. Обычно это делают всегда, кроме случаев, когда регистр несёт смысл (например, имена собственные в NER).

**Удаление шума.** Пунктуация, цифры, HTML-теги, эмодзи — обычно убираются. Но осторожно: иногда пунктуация важна (например, `!!!` в отзывах), а цифры — тоже (`цена 1000`). Для 20 Newsgroups полезно убрать email-адреса и URL.

**Токенизация.** Разбиение строки на токены. Простой `text.split()` работает плохо: «Привет, мир!» превратится в `['Привет,', 'мир!']` — пунктуация прилипла. Правильнее использовать `nltk.word_tokenize` или `RegexpTokenizer(r'\w+')`.

**Удаление стоп-слов.** Стоп-слова — это частые слова, не несущие смысла: «и», «в», «на», «the», «is». Их удаление уменьшает размер словаря и часто улучшает качество. Но осторожно: в анализе тональности слова «не», «никогда», «очень» — это стоп-слова, но они несут смысл. Поэтому в sentiment-задачах стоп-слова часто **не удаляют**.

**Стемминг vs лемматизация.** Стемминг отрезает окончания по эвристическим правилам: «кошки» → «кошк». Лемматизация приводит слово к словарной форме: «кошки» → «кошка». Лемматизация точнее, но медленнее и требует морфологического словаря. Для английского — `WordNetLemmatizer`, для русского — `pymorphy2`.

Покажем разницу:

```python
import re
import nltk
from nltk.corpus import stopwords
from nltk.stem import PorterStemmer, SnowballStemmer, WordNetLemmatizer
from nltk.tokenize import word_tokenize

text = """The cats were running in the park, chasing the mice!
         They didn't catch them, because the mice were too fast."""

# Токенизация
tokens = word_tokenize(text.lower())
print('Токены:', tokens[:15])

# Удаление пунктуации и не-букв
tokens_clean = [t for t in tokens if t.isalpha()]
print('После удаления пунктуации:', tokens_clean[:15])

# Удаление стоп-слов
stop_en = set(stopwords.words('english'))
tokens_no_stop = [t for t in tokens_clean if t not in stop_en]
print('Без стоп-слов:', tokens_no_stop[:15])

# Стемминг (Porter)
stemmer = PorterStemmer()
print('Стемминг:', [stemmer.stem(t) for t in tokens_no_stop])

# Лемматизация (WordNet)
lemmatizer = WordNetLemmatizer()
print('Лемматизация:', [lemmatizer.lemmatize(t, pos='v')
                       for t in tokens_no_stop])
```

Стемминг даст «runn», «chase», «mice»; лемматизация — «run», «chase», «mouse». Лемматизация «красивее», но работает медленнее.

**Собираем функцию предобработки.** В `sklearn` удобно передавать свою функцию в `CountVectorizer(preprocessor=..., tokenizer=...)`:

```python
def preprocess_ru(text):
    text = text.lower()
    text = re.sub(r'[^а-яё\s]', ' ', text)          # оставить только буквы
    tokens = text.split()
    stop_ru = set(stopwords.words('russian'))
    tokens = [t for t in tokens if t not in stop_ru and len(t) > 2]
    return [morph.parse(t)[0].normal_form for t in tokens]
```

Обратите внимание: предобработку лучше тестировать на нескольких примерах, чтобы увидеть, что получается на выходе. Ошибка в регексе или стоп-словах легко «убивает» полезную информацию.

> **Важное замечание.** Не существует «правильной» предобработки, универсальной для всех задач. В анализе тональности — одна, в классификации тем — другая, в NER — третья. Выбор зависит от задачи и проверяется экспериментально: сравните качество модели до и после.

##### Bag of Words

Простейшее векторное представление: **словарь всех слов корпуса** + **вектор частот** для каждого документа. Порядок слов теряется, но частоты сохраняются.

`CountVectorizer` из `sklearn` делает всё автоматически:

```python
from sklearn.feature_extraction.text import CountVectorizer

vectorizer = CountVectorizer(max_features=5000)  # ограничим словарь
X_bow = vectorizer.fit_transform(df['text'])
print(X_bow.shape)   # (n_documents, n_features)
```

Результат — **разреженная матрица** (sparse matrix). Большинство ячеек — нули, потому что каждый документ содержит лишь малую часть словаря. Хранить такую матрицу плотной (numpy array) было бы расточительно: для 3000 документов и 5000 признаков это 15 млн ячеек, из которых 99% — нули.

**Параметры `CountVectorizer`:**

- `max_features` — оставить только N самых частых слов. Без ограничения словарь может вырасти до десятков тысяч, и многие признаки будут встречаться в одном документе (мусор).
- `min_df` / `max_df` — отбросить слишком редкие (появляются в < `min_df` документах) и слишком частые (в > `max_df` документах) слова. `min_df=2` отбрасывает слова, встречающиеся один раз, — это обычно шум.
- `ngram_range` — учитывать ли n-граммы (см. раздел 5).
- `binary=True` — вместо частот использовать 0/1 (важно для некоторых моделей).

Посмотрим на словарь и на то, какие слова попали в документ:

```python
feature_names = vectorizer.get_feature_names_out()
print('Размер словаря:', len(feature_names))
print('Первые 20 слов:', feature_names[:20])

# Частоты в первом документе
first_doc = X_bow[0].toarray().ravel()
top_idx = np.argsort(-first_doc)[:10]
print('Топ-10 слов первого документа:')
for i in top_idx:
    if first_doc[i] > 0:
        print(f'  {feature_names[i]}: {int(first_doc[i])}')
```

BoW — это уже готовый признаковый набор, к которому можно применять **любую** модель классификации.

**Ограничения BoW:**

- Не учитывает порядок слов: «собака кусает человека» и «человек кусает собаку» — одинаковые векторы.
- Не различает информативные и неинформативные слова: «the» и «hockey» могут иметь одинаковый вес.
- Словарь растёт с размером корпуса, и многие признаки — шум.

Именно эти ограничения мотивируют TF-IDF и n-граммы.

##### TF-IDF

**TF-IDF** (Term Frequency — Inverse Document Frequency) — взвешивание частот слов с учётом их информативности:

$$\text{tf-idf}(t, d) = \text{tf}(t, d) \cdot \text{idf}(t)$$

где:

- $\text{tf}(t, d)$ — частота слова $t$ в документе $d$;
- $\text{idf}(t) = \log\frac{N}{n_t}$ — обратная частота документа, где $N$ — число документов, $n_t$ — число документов, содержащих слово $t$.

Интуиция: если слово встречается во **всех** документах (например, «the»), его idf близок к 0 — оно ничего не различает. Если слово встречается в **одном** документе, его idf максимален — оно уникально.

Формула на практике имеет варианты нормировки (например, `idf(t) = log((1+N)/(1+n_t)) + 1`), но идея одна.

```python
from sklearn.feature_extraction.text import TfidfVectorizer

tfidf = TfidfVectorizer(max_features=5000, min_df=2, max_df=0.7)
X_tfidf = tfidf.fit_transform(df['text'])
print(X_tfidf.shape)
```

**Что даёт TF-IDF на практике.** Типичный выигрыш над BoW — 2–5% accuracy. Но главное — он «автоматически» приглушает шум: частые слова (стоп-слова, общие слова типа «делать», «быть») получают маленький вес, а редкие специфичные — большой. Это часто позволяет обойтись **без удаления стоп-слов**: они и так получают малый вес.

Сравним BoW и TF-IDF:

```python
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import f1_score

X_tr_text, X_te_text, y_tr, y_te = train_test_split(
    df['text'], df['target'], test_size=0.3, random_state=42,
    stratify=df['target'],
)

for name, vec in [
    ('BoW', CountVectorizer(max_features=5000, min_df=2)),
    ('TF-IDF', TfidfVectorizer(max_features=5000, min_df=2, max_df=0.7)),
]:
    X_tr = vec.fit_transform(X_tr_text)
    X_te = vec.transform(X_te_text)
    clf = LogisticRegression(max_iter=1000, C=1.0).fit(X_tr, y_tr)
    pred = clf.predict(X_te)
    print(f'{name}: F1-macro = {f1_score(y_te, pred, average="macro"):.3f}, '
          f'размер словаря = {len(vec.get_feature_names_out())}')
```

> **Почему `TfidfVectorizer` «обучается» на train, а применяется к test?** Словарь и веса idf определяются по обучающей выборке. На тесте мы используем **тот же** словарь и **те же** idf, иначе будет утечка информации.

##### n-граммы

BoW и TF-IDF «не видят» словосочетаний. Фраза «not good» и «good» дадут одинаковый вклад в BoW, хотя означают противоположное. **n-граммы** решают эту проблему: признаками становятся не только отдельные слова, но и последовательности из $n$ слов.

- **Униграммы** ($n=1$) — отдельные слова.
- **Биграммы** ($n=2$) — пары слов: «not good», «very bad».
- **Триграммы** ($n=3$) — тройки.

```python
tfidf_ngrams = TfidfVectorizer(
    max_features=10000,
    ngram_range=(1, 2),      # униграммы + биграммы
    min_df=2,
)
X_ngrams = tfidf_ngrams.fit_transform(X_tr_text)
print('Размер словаря с биграммами:', X_ngrams.shape[1])
```

Размер словаря резко растёт, поэтому `max_features` и `min_df` становятся ещё важнее. На практике `ngram_range=(1, 2)` часто даёт выигрыш в 1–3% F1, но иногда эффект отсутствует — зависит от задачи.

##### Модели классификации текстов

Текстовые признаки — разреженные, многомерные, многие признаки коррелированы. Хорошо работают:

- **Multinomial Naive Bayes** — быстрый baseline. Предполагает, что слова в документе независимы (наивное допущение). Несмотря на это, для классификации текстов работает удивительно хорошо.
- **Logistic Regression** — линейный классификатор, часто лучший выбор для разреженных данных. Устойчив, интерпретируем (коэффициенты — это «вес» каждого слова), хорошо регулируется.
- **LinearSVC** — линейный SVM, обычно очень быстрый и точный. Часто даёт лучший F1 из трёх, но не выдаёт вероятности.
- **Random Forest / Gradient Boosting** — работают хуже на разреженных BoW-признаках, но на эмбеддингах (плотных векторах) могут быть конкурентны.

Сравним три базовые модели на TF-IDF:

```python
from sklearn.naive_bayes import MultinomialNB
from sklearn.svm import LinearSVC
from sklearn.metrics import classification_report

models = {
    'MultinomialNB': MultinomialNB(),
    'LogisticRegression': LogisticRegression(max_iter=1000, C=1.0),
    'LinearSVC': LinearSVC(C=0.5, max_iter=5000),
}

X_tr = tfidf.fit_transform(X_tr_text)
X_te = tfidf.transform(X_te_text)

for name, model in models.items():
    model.fit(X_tr, y_tr)
    pred = model.predict(X_te)
    f1 = f1_score(y_te, pred, average='macro')
    print(f'--- {name}: F1-macro = {f1:.3f} ---')
    print(classification_report(y_te, pred, target_names=df['label'].unique()))
```

Типичный результат на 20 Newsgroups:

- MultinomialNB: F1 ≈ 0.85
- LogisticRegression: F1 ≈ 0.87
- LinearSVC: F1 ≈ 0.88

Разница небольшая, но LinearSVC обычно стабильно выигрывает на этом типе данных.

**Кросс-валидация.** Как всегда, одна цифра на одном разбиении — плохая оценка. Используем кросс-валидацию с усреднением:

```python
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import Pipeline

pipe = Pipeline([
    ('tfidf', TfidfVectorizer(max_features=5000, min_df=2, max_df=0.7)),
    ('clf', LinearSVC(C=0.5, max_iter=5000)),
])

scores = cross_val_score(pipe, df['text'], df['target'],
                         cv=5, scoring='f1_macro')
print(f'F1-macro по фолдам: {scores.round(3)}')
print(f'Среднее: {scores.mean():.3f} ± {scores.std():.3f}')
```

`Pipeline` очень удобен: он объединяет векторизацию и модель в единый объект, который можно напрямую передать в `cross_val_score` или `GridSearchCV`. Внутри кросс-валидации `fit` векторизатора происходит только на обучающих фолдах — утечки нет.

##### Своя реализация Multinomial Naive Bayes

Чтобы понять, что «под капотом», реализуем Multinomial NB руками. Идея:

- Для каждого класса $c$ и слова $w$ оцениваем вероятность $P(w | c)$ по обучающим данным: сколько раз $w$ встретилось в документах класса $c$, поделённое на общее число слов в классе $c$.
- Применяем **сглаживание Лапласа**, чтобы избежать нулевых вероятностей: $P(w | c) = \frac{n_{w,c} + \alpha}{N_c + \alpha |V|}$, где $V$ — размер словаря, $N_c$ — число слов в классе $c$.
- Для предсказания используем теорему Байеса (в логарифмах, чтобы избежать underflow):

$$\log P(c | d) \propto \log P(c) + \sum_{w \in d} \log P(w | c)$$

```python
class MultinomialNBManual:
    def __init__(self, alpha=1.0):
        self.alpha = alpha
    
    def fit(self, X, y):
        self.classes_ = np.unique(y)
        n_classes = len(self.classes_)
        n_features = X.shape[1]
        self.log_prior_ = np.zeros(n_classes)
        self.log_likelihood_ = np.zeros((n_classes, n_features))
        
        for i, c in enumerate(self.classes_):
            X_c = X[y == c]
            # Приоры: доля класса в выборке
            self.log_prior_[i] = np.log(X_c.shape[0] / X.shape[0])
            # Суммируем частоты слов в классе
            word_counts = X_c.sum(axis=0)              # shape (n_features,)
            # Сглаживание Лапласа
            smoothed = word_counts + self.alpha
            total = smoothed.sum()
            # Логарифм вероятностей
            self.log_likelihood_[i] = np.log(smoothed / total)
        return self
    
    def predict(self, X):
        # X: разреженная матрица; умножаем на log_likelihood
        # Формула: log P(c) + X @ log P(w|c).T
        scores = X @ self.log_likelihood_.T + self.log_prior_
        # scores: (n_samples, n_classes)
        return self.classes_[np.argmax(scores, axis=1)]

# Сравним с библиотечной реализацией
from sklearn.naive_bayes import MultinomialNB

X_tr = tfidf.fit_transform(X_tr_text)
X_te = tfidf.transform(X_te_text)

nb_manual = MultinomialNBManual(alpha=1.0).fit(X_tr, y_tr)
nb_sklearn = MultinomialNB(alpha=1.0).fit(X_tr, y_tr)

print('Руками: ', f1_score(y_te, nb_manual.predict(X_te), average='macro'))
print('sklearn:', f1_score(y_te, nb_sklearn.predict(X_te), average='macro'))
```

Результаты должны совпасть (или почти совпасть — различия могут быть из-за обработки разреженных матриц и порядка операций). Реализация руками помогает увидеть, что «наивный Байес» — это буквально матричное умножение и сглаживание, а не «магия».

##### Векторные представления: word2vec и sentence transformers (кратко)

Классические BoW и TF-IDF «не понимают» семантику: «автомобиль» и «машина» для них — разные признаки, хотя означают одно и то же. **Эмбеддинги** — это плотные векторы, в которых близкие по смыслу слова находятся рядом.

**Word2Vec / GloVe / FastText** — модели, обученные на больших корпусах. Каждое слово получает вектор размерности 100–300. Для документа усредняют векторы всех его слов (или взвешенное среднее) — получают векторное представление документа.

**Sentence Transformers (BERT, RoBERTa, и др.)** — модели, которые кодируют **весь текст** целиком в один вектор. Дают заметно лучшее качество, но требуют GPU для обучения и больших корпусов.

Пример использования sentence transformers:

```python
# pip install sentence-transformers

# Классификация на эмбеддингах
from sklearn.linear_model import LogisticRegression
clf_emb = LogisticRegression(max_iter=1000).fit(X_emb, y_tr)
# ... и сравнить с TF-IDF
```

На 20 Newsgroups эмбеддинги обычно дают **такое же или немного лучшее** качество, чем TF-IDF, но требуют в разы больше ресурсов. На других задачах (например, где мало обучающих данных или важна семантика) выигрыш может быть значительным.

> **Практическое правило.** Всегда начинайте с TF-IDF + линейной модели. Если качество не устраивает — попробуйте эмбеддинги. Но не начинайте с BERT: это дороже по времени, памяти и сложнее в отладке.
