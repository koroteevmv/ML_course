### Классификация на реальных данных

#### Цель работы

Познакомиться с основными приёмами работы с классификационными моделями на реальных данных и с типичными проблемами, которые в них встречаются: дисбаланс классов, разный масштаб признаков, коррелированные признаки, выбросы, нелинейная разделимость. Научиться строить логистическую регрессию на реальных данных, интерпретировать её результаты, оценивать статистическую достоверность предсказаний и понимать, когда accuracy обманчива.

#### Подготовка данных

Работаем с реальным медицинским датасетом **Breast Cancer Wisconsin** — данные о диагностике рака груди по характеристикам клеточных ядер. Это классический публичный датасет, встроенный в `sklearn`.

**Признаки** (30 числовых): характеристики ядер клеток, полученные из изображений биопсии: радиус, текстура, периметр, площадь, гладкость, компактность и т.д. Для каждого — среднее, стандартное отклонение и «худшее» (максимальное) значение.

**Целевая переменная**: злокачественная (malignant, `target = 0`) или доброкачественная (benign, `target = 1`) опухоль.

Для медицинской задачи удобнее работать с «положительным» классом = злокачественная опухоль (то, что мы хотим обнаружить). Поэтому мы **инвертируем** метку: `y = 1 - target`, так что `y = 1` — злокачественная, `y = 0` — доброкачественная. Доля злокачественных ~37%.

Скрипт ниже загружает данные и сохраняет в CSV. Если у вас есть интернет, можно не запускать: в ноутбуке данные загружаются напрямую через `load_breast_cancer()`.

```python
# prepare_data.py
from sklearn.datasets import load_breast_cancer


def prepare():
    data = load_breast_cancer(as_frame=True)
    df = data.frame.copy()
    df['target'] = 1 - data.target  # malignant = 1, benign = 0
    # Переименуем для читаемости
    rename = {c: c.replace(' ', '_') for c in df.columns if ' ' in c}
    df = df.rename(columns=rename)
    df.to_csv('breast_cancer.csv', index=False)
    print(f'Сохранено {len(df)} строк в breast_cancer.csv')
    print(f'Доля злокачественных: {df.target.mean():.3f}')
    print('Столбцы:', list(df.columns))


if __name__ == '__main__':
    prepare()
```

#### Методические указания

##### Почему реальные данные — это сложно

На синтетических данных из предыдущих лабораторных всё было «удобно»: признаки одного масштаба, классы сбалансированы, границы чёткие. В реальных данных — почти всегда наоборот. На этом датасете мы увидим сразу несколько типовых проблем:

| Проблема | Как проявляется здесь | Почему опасна |
|---|---|---|
| **Дисбаланс классов** | 37% злокачественных, 63% доброкачественных | accuracy «обманывает»: модель может вообще не находить больных |
| **Разный масштаб** | площадь ~1000, гладкость ~0.1 | градиентный спуск плохо сходится, коэффициенты несравнимы |
| **Мультиколлинеарность** | `radius`, `perimeter`, `area` коррелируют > 0.99 | коэффициенты нестабильны, их нельзя интерпретировать по отдельности |
| **Выбросы** | есть в «worst»-признаках | средние и дисперсии искажаются |
| **Нелинейная разделимость** | классы частично перекрываются | линейная модель не даст идеального результата |

Дальше мы будем последовательно с этим разбираться.

##### Baseline: почему accuracy без контекста бесполезна

Посмотрим на матрицу ошибок:

**Вывод:** для задач с дисбалансом нужны другие метрики — precision, recall, F1, ROC-AUC. К ним мы вернёмся после того, как обучим настоящую модель.

##### Логистическая регрессия без масштабирования — и почему это плохо

Попробуем обучить логистическую регрессию «как есть» — без масштабирования признаков:

```python
from sklearn.linear_model import LogisticRegression

model_raw = LogisticRegression(max_iter=1000).fit(X_tr, y_tr)
y_pred_raw = model_raw.predict(X_te)

print(f'Accuracy: {accuracy_score(y_te, y_pred_raw):.3f}')
print(f'Число итераций: {model_raw.n_iter_[0]}')
```

`sklearn` выведет **`ConvergenceWarning`**: «lbfgs failed to converge». Это происходит потому, что признаки имеют разный масштаб: оптимизатор `lbfgs` (а также любой градиентный спуск) «мечется» по поверхности ошибки, где вдоль одних осей всё гладко, а вдоль других — круто. Формально он сходится, но за намного большее число итераций, и часто — не до конца.

Проверим, что будет с «ручным» градиентным спуском (подробно — в самостоятельных заданиях):

```python
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def batch_gd(X, y, alpha=0.01, n_iters=500):
    n, p = X.shape
    X_design = np.hstack([np.ones((n, 1)), X])
    w = np.zeros(p + 1)
    losses = []
    for _ in range(n_iters):
        sigma = sigmoid(X_design @ w)
        grad = X_design.T @ (sigma - y) / n
        w -= alpha * grad
        loss = -np.mean(y * np.log(sigma + 1e-15) +
                        (1 - y) * np.log(1 - sigma + 1e-15))
        losses.append(loss)
    return w, losses

# Без масштабирования
w_raw, losses_raw = batch_gd(X_tr.values, y_tr.values, alpha=0.001, n_iters=500)
print(f'Loss без масштабирования: {losses_raw[0]:.3f} → {losses_raw[-1]:.3f}')

# Со стандартизацией
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler().fit(X_tr)
X_tr_sc = scaler.transform(X_tr)
w_sc, losses_sc = batch_gd(X_tr_sc, y_tr.values, alpha=0.1, n_iters=500)
print(f'Loss со стандартизацией:  {losses_sc[0]:.3f} → {losses_sc[-1]:.3f}')
```

Без масштабирования функция ошибки почти не уменьшается — модель «застревает». Со стандартизацией — падает быстро. Это не тонкость: без масштабирования обучать линейные модели на реальных данных **нельзя**.

##### Логистическая регрессия со стандартизацией и метрики

Соберём «правильный» конвейер: `StandardScaler` → `LogisticRegression`.

```python
from sklearn.pipeline import Pipeline
from sklearn.metrics import (roc_auc_score, precision_score,
                              recall_score, f1_score, roc_curve)

pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('clf', LogisticRegression(max_iter=1000)),
])
pipe.fit(X_tr, y_tr)

y_pred = pipe.predict(X_te)
y_proba = pipe.predict_proba(X_te)[:, 1]

print(f'Accuracy:  {accuracy_score(y_te, y_pred):.3f}')
print(f'Precision: {precision_score(y_te, y_pred):.3f}')
print(f'Recall:    {recall_score(y_te, y_pred):.3f}')
print(f'F1:        {f1_score(y_te, y_pred):.3f}')
print(f'ROC-AUC:   {roc_auc_score(y_te, y_proba):.3f}')
```

Типичные значения для этого датасета:

- **Accuracy ≈ 0.97** — кажется, отлично.
- **Precision ≈ 0.98** — из предсказанных «больных» 98% действительно больны.
- **Recall ≈ 0.94** — нашли 94% реально больных.
- **F1 ≈ 0.96** — гармоническое среднее.
- **ROC-AUC ≈ 0.995** — почти идеальная модель.

Разница с dummy колоссальная: dummy даёт 0.63 accuracy, а наша модель — 0.97. Но главное не в accuracy, а в том, что модель **находит больных** — recall = 0.94 при precision = 0.98. Это и есть её настоящая ценность.

Построим матрицу ошибок и ROC-кривую:

```python
fig, axes = plt.subplots(1, 2, figsize=(14, 5))

# Матрица ошибок
cm = confusion_matrix(y_te, y_pred)
sns.heatmap(cm, annot=True, fmt='d', cmap='Blues', cbar=False, ax=axes[0],
            xticklabels=['Доброкач.', 'Злокач.'],
            yticklabels=['Доброкач.', 'Злокач.'])
axes[0].set_xlabel('Предсказано'); axes[0].set_ylabel('Истина')
axes[0].set_title('Матрица ошибок (логистическая регрессия)')

# ROC-кривая
fpr, tpr, _ = roc_curve(y_te, y_proba)
axes[1].plot(fpr, tpr, linewidth=2, label=f'AUC = {roc_auc_score(y_te, y_proba):.3f}')
axes[1].plot([0, 1], [0, 1], 'k--', label='Случайный')
axes[1].set_xlabel('False Positive Rate')
axes[1].set_ylabel('True Positive Rate (Recall)')
axes[1].set_title('ROC-кривая')
axes[1].legend()

plt.tight_layout(); plt.show()
```

**Что означает матрица ошибок.** Для медицинской задачи:

- **True Positive (TP)** — больной правильно определён как больной.
- **False Negative (FN)** — больной пропущен, ему сказали «здоров» → **самая дорогая ошибка**.
- **False Positive (FP)** — здоровому сказали «болен» → дополнительное обследование, стресс, но не смертельно.
- **True Negative (TN)** — здорового правильно определили.

В нашем случае FP и FN примерно сбалансированы, но в реальной медицинской практике FN в разы дороже FP, поэтому обычно сдвигают порог в сторону меньшего recall'а (то есть более часто говорят «болен»). Порог и ROC-кривые подробно разбираются в отдельной лабораторной.

##### Дисбаланс классов и `class_weight`

У нашей модели recall = 0.94 — это **средняя** точность по всем больным. Но что если модель «не видит» часть больных? Особенно тех, у кого признаки «пограничные»?

Один из способов улучшить recall миноритарного класса — передать в модель информацию о том, что классы неравноценны. Параметр `class_weight='balanced'` автоматически назначает веса, обратно пропорциональные частоте класса:

```python
pipe_bal = Pipeline([
    ('scaler', StandardScaler()),
    ('clf', LogisticRegression(max_iter=1000, class_weight='balanced')),
])
pipe_bal.fit(X_tr, y_tr)
y_pred_bal = pipe_bal.predict(X_te)
y_proba_bal = pipe_bal.predict_proba(X_te)[:, 1]

print('Без весов:')
print(f'  Precision: {precision_score(y_te, y_pred):.3f}, '
      f'Recall: {recall_score(y_te, y_pred):.3f}, '
      f'F1: {f1_score(y_te, y_pred):.3f}')
print('С class_weight=balanced:')
print(f'  Precision: {precision_score(y_te, y_pred_bal):.3f}, '
      f'Recall: {recall_score(y_te, y_pred_bal):.3f}, '
      f'F1: {f1_score(y_te, y_pred_bal):.3f}')
```

Типичная картина: recall вырастает с 0.94 до 0.96–0.97, precision немного падает (0.98 → 0.96). Это компромисс: мы ловим больше больных ценой нескольких ложных тревог. Для медицинской задачи это обычно оправдано.

**Практическое замечание.** `class_weight='balanced'` — это простой приём, но не серебряная пуля. Иногда он не нужен (если признаки уже хорошо разделяют классы), иногда — вреден (если миноритарный класс — просто шум). К нему стоит прибегать, когда бизнес-задача требует высокого recall, и метрики показывают, что модель «пропускает» важные случаи.

##### Интерпретация коэффициентов

Одно из главных преимуществ логистической регрессии — **интерпретируемость**. Коэффициенты показывают вклад признаков в предсказание. Но с реальными данными есть нюансы.

Выведем коэффициенты (после стандартизации они сравнимы между собой):

```python
coefs = pipe.named_steps['clf'].coef_[0]
features = X.columns

coef_df = pd.DataFrame({
    'feature': features,
    'coef': coefs,
}).sort_values('coef', key=abs, ascending=False)

print(coef_df.head(10))
```

**Что важно понимать:**

1. **После стандартизации** коэффициенты сравнимы: они показывают, насколько сильно признак «толкает» предсказание при изменении на одно стандартное отклонение.
2. **Знак коэффициента** — направление влияния. Положительный коэффициент → рост признака увеличивает вероятность злокачественности; отрицательный → уменьшает.
3. **Мультиколлинеарность искажает коэффициенты.** `mean_radius`, `mean_perimeter`, `mean_area` — три почти одинаковых признака. Модель может «раздать» им произвольные коэффициенты (один большой положительный, другой большой отрицательный), которые в сумме дают верное предсказание, но по отдельности не интерпретируются. Это легко увидеть:

```python
print(coef_df[coef_df.feature.isin(
    ['mean_radius', 'mean_perimeter', 'mean_area',
     'worst_radius', 'worst_perimeter', 'worst_area'])])
```

Скорее всего, вы увидите, что у одних «размерных» признаков коэффициент большой положительный, у других — большой отрицательный, хотя все они измеряют размер. Это и есть артефакт мультиколлинеарности.

Визуализируем топ-10 коэффициентов:

```python
top = coef_df.head(15).iloc[::-1]
plt.figure(figsize=(10, 6))
colors = ['tab:red' if c > 0 else 'tab:blue' for c in top['coef']]
plt.barh(top['feature'], top['coef'], color=colors)
plt.xlabel('Коэффициент (после стандартизации)')
plt.title('Топ-15 признаков по модулю коэффициента\n'
         '(красный — повышает риск злокачественности, синий — понижает)')
plt.axvline(0, color='k', linewidth=0.8)
plt.tight_layout(); plt.show()
```

**Интерпретация:** самые сильные признаки — «worst»-характеристики (максимальные значения по клеткам): `worst_concave_points`, `worst_perimeter`, `worst_area`. Это логично: чем больше «худшие» (то есть самые аномальные) клетки в образце, тем выше вероятность злокачественности.

##### Статистическая достоверность: bootstrap и калибровка

Одна цифра accuracy = 0.97 или AUC = 0.995 не говорит о стабильности. Мы получили её на одном конкретном разбиении train/test — при другом разбиении цифра может отличаться на несколько процентных пунктов. Оценить разброс помогает **bootstrap**.

**Bootstrap для метрик.** Многократно семплируем test с возвращением и считаем метрику на каждом семпле:

```python
def bootstrap_ci(y_true, y_score, metric_fn, n_bootstrap=1000,
                 alpha=0.05, seed=0):
    rng = np.random.RandomState(seed)
    n = len(y_true)
    values = []
    for _ in range(n_bootstrap):
        idx = rng.choice(n, size=n, replace=True)
        if len(np.unique(y_true.iloc[idx])) < 2:
            continue  # пропускаем «вырожденные» семплы
        values.append(metric_fn(y_true.iloc[idx], y_score[idx]))
    values = np.array(values)
    lower = np.percentile(values, 100 * alpha / 2)
    upper = np.percentile(values, 100 * (1 - alpha / 2))
    return values, (lower, upper)

from sklearn.metrics import roc_auc_score

auc_values, auc_ci = bootstrap_ci(
    y_te, y_proba, roc_auc_score, n_bootstrap=1000
)
print(f'AUC = {roc_auc_score(y_te, y_proba):.4f}')
print(f'95% CI: [{auc_ci[0]:.4f}, {auc_ci[1]:.4f}]')

plt.figure(figsize=(8, 4))
sns.histplot(auc_values, bins=40, kde=True)
plt.axvline(roc_auc_score(y_te, y_proba), color='r', linestyle='--',
            label='Точечная оценка')
plt.axvline(auc_ci[0], color='gray', linestyle=':')
plt.axvline(auc_ci[1], color='gray', linestyle=':', label='95% CI')
plt.xlabel('ROC-AUC')
plt.title('Bootstrap-распределение ROC-AUC')
plt.legend()
plt.show()
```

Типичный результат: AUC ≈ 0.995, CI ≈ [0.985, 1.000]. Разброс небольшой — оценка стабильна. Если бы CI был широким (например, [0.90, 0.99]), это был сигнал, что test-выборки слишком мало для надёжной оценки.

**Калибровка.** Predicted probability — это ещё не «реальная частота». Модель может говорить «0.9», а среди объектов с $\hat{p} \approx 0.9$ реально больных только 70%. Кривая калибровки показывает, насколько предсказанные вероятности соответствуют эмпирическим частотам:

```python
from sklearn.calibration import calibration_curve

prob_true, prob_pred = calibration_curve(
    y_te, y_proba, n_bins=10, strategy='uniform'
)

plt.figure(figsize=(8, 5))
plt.plot(prob_pred, prob_true, 'o-', label='Модель')
plt.plot([0, 1], [0, 1], 'k--', label='Идеальная калибровка')
plt.xlabel('Средняя предсказанная вероятность')
plt.ylabel('Реальная частота злокачественных')
plt.title('Кривая калибровки')
plt.legend()
plt.grid(True)
plt.show()
```

**Как читать:** точки должны лежать вдоль диагонали. Если модель «переуверена» (точки ниже диагонали при высоких $\hat{p}$), это значит, что её вероятности завышены. Логистическая регрессия обычно калибрована неплохо, но с регуляризацией и на малых выборках могут быть отклонения.

**Зачем это бизнесу.** Если модель используется для принятия решений с денежным исходом (например, страховка решает, какую премию назначить), важны именно калиброванные вероятности, а не только accuracy. Если модель говорит «0.9», это должно означать «в 90% случаев». Для медицинской задачи калибровка тоже полезна, но там важнее recall.

##### Регуляризация

По умолчанию `LogisticRegression` использует **L2-регуляризацию** с параметром `C = 1.0`. Параметр `C` — обратная сила регуляризации: чем меньше `C`, тем сильнее штраф за большие коэффициенты.

Посмотрим, как `C` влияет на коэффициенты и качество:

```python
Cs = [0.001, 0.01, 0.1, 1, 10, 100]
results = []

for C in Cs:
    pipe_c = Pipeline([
        ('scaler', StandardScaler()),
        ('clf', LogisticRegression(max_iter=1000, C=C)),
    ]).fit(X_tr, y_tr)
    y_pred_c = pipe_c.predict(X_te)
    y_proba_c = pipe_c.predict_proba(X_te)[:, 1]
    results.append({
        'C': C,
        'Accuracy': accuracy_score(y_te, y_pred_c),
        'F1': f1_score(y_te, y_pred_c),
        'AUC': roc_auc_score(y_te, y_proba_c),
        'L2_norm_coef': np.linalg.norm(pipe_c.named_steps['clf'].coef_),
    })

pd.DataFrame(results).round(4)
```

**Что обычно видно:**

- При очень малых `C` (сильная регуляризация) коэффициенты «сжимаются» к нулю, модель становится слишком простой — accuracy и F1 падают (недообучение).
- При очень больших `C` (слабая регуляризация) модель может переобучиться на train, но на этом датасете (569 строк, 30 признаков) — редко.
- «Сладкая точка» — где-то в районе `C = 0.1`–`1`.

На нашем датасете регуляризация не критична (30 признаков — не так много), но на реальных данных с сотнями признаков она критична. Общее правило: **использовать `C`, подобранный кросс-валидацией**, а не значение по умолчанию.
